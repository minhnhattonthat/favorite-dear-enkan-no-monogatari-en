# Skill gotchas (one line each: the reference file it belongs in, then the fact)

- references/pipeline.md §Recon: on a re-release of an already-translated game, matching the old font's pixel rows found a false base (11 rows by chance); disassembling the old draw-glyph routine's twin (instruction match with immediates masked, `tools/codefind.py`) gave the real font pointer and showed the bit order had flipped (LSB-first -> MSB-first).
- references/pipeline.md §Recon: a sequel/re-release can change a directory's entry format (u32 sector + u32 bytes -> u16 sector + u16 count) while keeping entry indices; search for the old sector sequence at every width/stride, not just the old layout.
- references/emulator-qa.md §Per-emulator facts: PCSX-Redux (nightly 32338) dynarec crashes the emulator process (exit 0xC0000374, heap corruption) ~1800 frames into this game's FIN.EXE staff roll; `--debugger` (interpreter) plays it through. When emu.py exits with a Windows crash code, retry the run in interpreter mode before suspecting the game.
- references/emulator-qa.md §Debug tool: porting a warp to a re-release, map each old RAM address through the code that builds it (lui/lo window match with immediates masked, vote over all sites: `tools/addrmap.py`); 8 of 9 game-1 addresses came out in one pass. A table that "disappears" may have changed form (here 9-byte names -> u16 name hashes): disassemble the loader instead of searching for the old bytes.
- references/pipeline.md §Extract: on a re-release, the old game's text regions moved as blocks but 5 new strings sat outside them, reached only by lui/addiu (no u32 pointer, below the scanner's 3-code minimum: 男/女 one kanji each). Sweeping every lui+immediate and u32 in the EXE for a target that starts a valid FFFF-terminated string, then triaging hits outside the regions, found them in one pass (noise: code tables decode as glyph soup at every 2-byte offset).
