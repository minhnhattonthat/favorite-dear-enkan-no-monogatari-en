# Text engine

Same engine as game 1 (`../favorite-dear-en/docs/re/text.md`, `events.md`): the same printers, control codes and
event-script grammar, at new addresses. What differs is listed here; anything not listed is game 1's, marked guess
until a phase needs it.

## Encoding (verified 2026-11-21: `tests/test_recon.py` decodes and re-encodes an EXE string byte-exact; event text
decodes as sentences, e.g. GDATA entry 397 "よう、天使様！ / なんの用だい？")

16-bit little-endian codes = font cell index, **game 1's layout** (`tbl/jp.tbl`, generated by `tools/mktbl.py`):
0x000 blank, 0x001-0x014 punctuation set A (stand-ins ､｡･:?! ...), 0x015 ＄, 0x016-0x01F ０-９, 0x020-0x022 ＫＯＸ,
0x023-0x071 hiragana, 0x072-0x0BD katakana, 0x0BE-0x57A kanji, 0x57B-0x5AD ，．Ａ-Ｚａ-ｚ, 0x5AE-0x5B3 ぢヌユヲヂヅ,
0x5CD-0x5E0 punctuation set B, then a second kanji block.
- Cells 0x0BE-0x57C (all first-block kanji) and most of 0x5EA-0x66B are bit-identical to game 1's, so they take
  game 1's hand-checked characters. Kana, punctuation and Latin were redrawn but keep the layout.
- Changed against game 1: ②③④ (0x5B4 0x5BF 0x5CC) and ￥ (0x5E8) are gone (0x5B4-0x5CB are kanji; 0x5CC, 0x5E8,
  0x5E9 blank; 0x5E9 decodes as 〿 as in game 1). 0x66C-0x6EF are new kanji (last glyph 0x6EF 築, incl. ／ 0x6E1);
  15 cells in 0x5F9-0x65D are blank. Changed/new cells take the MS Gothic match (`tools/fontmatch.py`, all
  159 checked on `work/recon/matched.png`; 0x68C fixed by eye to 揃).
- **NCODES = 0x6F0** (game 1: 0x66C): `tools/gdata.py`, `evscript.py`, `scantext.py` use it.

## Font (verified: disassembly)

12x12 1bpp, one 192 px wide image (16 cells per row, 24 bytes per pixel row), cell (c & 15, c >> 4): game 1's
format, except **bits are MSB-first** (bit 7 = leftmost; pixel read 0x800D6CFC tests `1 << (7 - (px & 7))`; game 1
read bit 0 first). Draw-glyph 0x800D5888 (game 1 0x800FC97C) passes the font pointer **0x80109EC0 = PSX.EXE file
0xFA6C0**; glyph fetch 0x800D6BB4 (game 1 0x800FDCA8). 0x6F0 cells = 0x7E90 bytes, to PSX.EXE 0x102550.
`python -X utf8 tools/font.py sheet work/disc/tree/PSX.EXE out.png 0x6F0` draws it.

## English (phase 5, verified in the marker build: `work/qa/p5/marker/ev_kaiwa1`, "[e835.1F2A]The quick...")

Game 1's pair glyphs (`../favorite-dear-en/docs/re/text.md` §English; why not VWF: the printer places 12x12 cells
on a 4-px grid, nothing composes a line). A halfword 0x2020-0xFEFF is two letters (low byte left), bytes 0x20-0x84
of `fonts/en6x12.txt`; `tools/en.py` encodes (an odd letter before a control code gets a space partner).
- `asm/pair.inc` hooks the glyph fetch (its first two instructions are game 1's): for a pair it builds the cell in a
  288-byte scratch image and renders cell 0 of that. **MSB-first here**: `tools/font_en.py` stores each glyph row in
  bits 7..2, and the hook writes byte 0 = left | right >> 6, byte 1 = right << 2 (`tests/test_insert.py`).
- Sites: PSX.EXE glyph fetch 0x800D6BB4 and OMK.EXE 0x800D976C (same bytes), each with the hook in its own free run
  (`space.md`, `insert.HOOKS`); TITLE/EPILOG.EXE renderer 0x80050494 (game 1 0x800526E8, same prologue
  `addiu sp,-0x40 / sw ra,0x3c(sp)`, pixel read 0x800506EC also MSB-first) via `asm/epilog.asm` (file grows one
  sector, a stub copies the blob to 0x80170000).
- Builds: `python -X utf8 tools/build.py --mode marker|ruler|torture` -> `build/fd3_en_<mode>.cue`. Marker mode
  keeps every row's control codes and width (k glyphs -> 2k letters); two scripts still outgrow their sectors
  (+8 bytes of id tag) and move to the end of GDATA.BIN, their entries rewritten in the six EXEs that carry the
  directory (`insert.EXE_DIRS`): the relocation path is exercised by the marker build. Torture mode puts the glyph
  torture line on each script's first row and `insert.TORTURE_ROWS` (ev_kaiwa1, battle_t0101), rulers elsewhere.
- Single-string overrides: `build.py --mode marker --qa 'PSX.138F10=<text>{end}' [--qa ...]` -> `build/fd3_en_marker_qa`
  writes the text to 0x80193800 (OMK -0x1840; `space.md`) and repoints every u32 pointer to the row in both EXEs
  (rows with no u32 pointer, e.g. the save menu 0x141C2C.., are refused). The width gate's menu measurements
  (`docs/windows.tsv`) used it.
- Staff roll (FIN.EXE): marker mode writes full-width `[Fn]` + filler in place (same byte length); English uses
  game 1's FIN pair-glyph hook, re-found (§Credits).
- Grown EXE strings (phase 7): `insert.exe_text` moves a string longer than its slot to `insert.REPOINT`
  (0x80193200-0x80193600 since the name-entry port; OMK.EXE -0x1840) and rewrites every aligned u32 pointing at it, in both EXEs (50 strings,
  ~816 bytes: place names "X Isle"/"X River" etc.); the old slot keeps a cut copy. Code-addressed strings can't move:
  PSX.14F670 平和度 and the 男/女 pair (0x14F68C) are read by fixed 8-byte lwl/lwr copies, so they are "Peace", "M",
  "F" in place.

## Printer and control codes (guess: same code as game 1, found by instruction match `codefind`)

Game 1's routines exist here at: EXE-string printer 0x800D517C (game 1 0x800FC270), face/number helper 0x800D6D38
(0x800FDE28), event printer 0x800A5C48 (0x800CC9EC), event loader 0x800A13DC (0x800C7FF0). `tbl/jp.tbl`'s control
lines (FFFF end, FFFE n, FFFC wait, FF00/FF10/FF90/FF20/FFE0) and `tbl/ev.tbl` (event printer) are copied from game
1; every event script sweeps with game 1's grammar and printer-argument table (below), which supports them.

## Script location

- **Event scripts in GDATA.BIN: 568 directory entries** whose header is `u16 6, u16 vars, u16 code` (`tools/gdata.py
  events`), ~750K characters (estimate; game 1 ~550K). `tools/evscript.py check` (game 1's parser, NCODES 0x6F0,
  files from the u16 directory) sweeps all 568 end to end: 13,261 text segments, 0 failures (`tests/test_recon.py`).
  Format, opcodes, messages, references: `../favorite-dear-en/docs/re/events.md` (same grammar).
- **Reuse of game 1's translation: 7,873 of 12,628 text segments (62%), 423K of 761K characters (56%) are verbatim
  game-1 `jp` rows** (`../favorite-dear-en/script/events/*.tsv` + `exe.tsv`), so the translation memory covers over
  half the script before any fuzzy matching.
- Load buffer: the loader (0x800A13DC) reads its file table at 0x80148C6C and loads a script at **RAM 0x80148CBC**
  (game 1 0x8016C608), inside the zero run PSX.EXE 0x139456-0x1404BE (RAM 0x80148C56-0x8014FCBE): room for ~0x7000
  bytes. The largest script uses 0x6C78 bytes (entry 747). Same limit as game 1, which fitted English with pair
  glyphs (codes >= 0x2020, `EN_LO` in `evscript.py`); `space.md`.
- **PSX.EXE strings: 952 strings / 29.9 KB** (`tools/scantext.py work/disc/tree/PSX.EXE --regions`), FFFF-terminated,
  main regions 0x131DC4-0x139030 (place names, items, skills, fairy/tutorial dialogue: 0x132EF0-0x1364BC holds 578)
  and 0x1409A4-0x142278 (system/memory-card messages), plus scattered short ones. Pointers: 433 strings have a u32
  vaddr pointing at them, 317 a record pointer up to 30 bytes before (game 1's record form), 202 neither (lui/addiu
  pairs or computed). vaddr = file offset - 0x800 + 0x80010000.
- **EXE text map (verified 2026-11-21, phase 4: `tests/test_extract.py` roundtrip + coverage):** game 1's two regions
  moved: **0x132398-0x139030** (game 1 0x155F3C-0x15CAB0) and **0x141C2C-0x142278** (game 1 0x1660E0-0x16667E);
  inside them only game 1's three u32 pointer tables are non-text: 0x132C74-0x132EF0, 0x1364BC-0x136DD0 (0x914,
  game 1 0x8E0), 0x138D50-0x138EE0. 0x1409A4-0x141C2C is the event-name/code tables (glyph soup; game 1 excluded the
  same). Name-entry grids 0x184EA4 (51 cells) and 0x184F64 (219 cells) (game 1 0x17DA4 / 0x17E64). Five strings
  outside the regions are built by lui/addiu in code, found by sweeping every lui+immediate and u32 into the EXE
  for a valid string start: 0x1322B0 ユリアナ and 0x1322BC アンドラング (a record's +0x574/+0x578, code 0x800DA168),
  0x14F670 平和度, 0x14F68C/0x14F690 男/女 (a 4-byte table). Every other sweep and scan hit is code/tables. Not
  text: 2-character Shift-JIS debug labels at 0x14F5E0-0x14F650 (任務 待機 放浪 ...; in game 1 too, never extracted).
- **OMK.EXE copies** (byte-identical, test): PSX region 1 + 0x1322B0 strings +0x224C, region 2 -0x1934, 0x14F670
  strings -0x18FC, grids and the card title -0x1840 (`extract.omk_delta`). Its GDATA directory (0x16EA04) equals
  PSX.EXE's. Small EXEs (FD_BALL, GOVER, PS_MOV, EPILOG, FD_MOV, _LOADE, SLPS) have no font-code text (scan hits are
  library code, as in game 1); only their Shift-JIS card titles.
- **Event rows:** 568 script entries, 566 sectors: entries 902 and 932 are entries 520 and 739 again
  (`extract.EVENT_ALIASES`). 12,617 text rows in 561 files. 1,197 rows are verbatim game-1 rows that game 1 left
  untranslated as glyph soup (a per-scene substitution table never found; game 1's glossary "Decisions from earlier
  batches"), notes `untranslated there (glyph soup in game 1)`; the marker build shows whether they are ever drawn.
- **OMK.EXE carries the same 952 strings** (identical decoded set) at its own offsets: a second text site.
- Shift-JIS: memory-card titles "フェイバリットディア　円環の物語　ゲームデータ" (PSX.EXE 0x18A93C, OMK.EXE 0x1890FC) and
  "...クリアデータ" (EPILOG.EXE 0x46180 and 0x46968, FD_BALL.EXE 0x40678, PS_MOV.EXE 0x3F254); test-build title
  ＦＡＶＯＲＩＴＥ　ＤＥＡＲ　ＴＥＳＴ at 0x11A4 of EPILOG/FD_BALL/PS_MOV (as in game 1). The other hits are font/code noise.
- Small EXEs (FD_BALL, GOVER, PS_MOV, EPILOG, FIN, FD_MOV, SLPS_032.86, _LOADE): 1-26 font-code scan hits each,
  game 1 found these to be code/tables; recheck in phase 4.

## OMK mini events (verified 2026-11-22: RAM dumps + the English build seen in game)
- The Omake menu's "Mini Event" plays a script that has no GDATA entry: OMK.EXE carries it pre-loaded in its copy
  of the script buffer, code at file 0x13B708-0x13EB86 (RAM 0x8014AF08.., pc 0 = a `0x28` goto), and runs it in
  place (`work/qa/p8/omkmini` RAM dumps: the RAM copy equals the file copy until the script runs). Its argument table
  is OMK's own, 234 halfwords at file 0x13B4C4 (followed by "sample.bmp"); with it `evscript.Script` parses 38 text
  segments cleanly (`extract.omk_mini_script` prepends a synthetic header). Same printer codes as GDATA events.
- PSX.EXE's post-buffer data follows at 0x13EB8A, so the code cannot grow: `insert.omk_mini_edit` rebuilds the
  script (refs remapped by `rebuild`) and zero-fills the rest of the slot. English (pair glyphs): 0x32D4 of 0x347E
  bytes. Rows: `script/omk.tsv` (ids `omk.<file offset>`), linted as events; marker builds leave it Japanese.
- Scenes (speaker 0100 first, 0000 second): Sievas/Fiana (the Kvaal church painting), Reiv/Sievas, a thief in
  Juliana's castle, Sievas/Felimi (the soiree), Kane(?) and a thief, Yaruru/Tia (the carving), Ryudral/Yaruru (Rush),
  Fiana/Griffin (Beowulf), Ashe/Reiv, Griffin/Dian, Nasadia/Felimi, Lydia/her brother, Juliana/Nasadia.
- Scene choice (verified 2026-11-22, all 12 played): pc 0x0D `007E 8002` reads the scene number the EXE passes into
  var 2; `0052 8002 1 <t1> 2 <t2> .. 12 <t12>` at pc 0x16 (setup) and pc 0x40 (scene body) switch on it. The Omake
  menu always passed 1 in the warp; warp.lua `MINI=N` rewrites every case target to case N's (`work/qa/p8/mini/`).

## Credits (verified: decoded)

No DATA/STAFF.TXT on this disc: the staff roll is **plain Shift-JIS inside DATA/FIN.EXE 0xF440-0x10D21** (6,369
bytes, 562 CRLF-ended lines then the 0xFF at 0x10D21; extracted as `script/staff.tsv` FIN.<line>, 272 rows; one
u32 at FIN.EXE 0x35E90 points at its start; game 1's STAFF.TXT used +1-shifted bytes and 0E 0B breaks). It starts
`　 / # / 　　　　声の出演 / シーヴァス・フォルクガング / 　　　　　　小川　雄一郎 ...` and ends with `\`; `#`, `\` and `$`-style
single-byte line codes as in game 1 (guess). Inside it, FIN.EXE 0x103E0 starts a section フェイバリットディア / オリジナル制作スタッフ /
ビジュアルＣＧ ... (the original game's staff).

English (phase 7, verified: `work/qa/p7/credits/credits_roll`, e.g. f012900 "Lily / Hiromi Nishida", clean):
`asm/fin.asm` is game 1's hook at this disc's addresses. `glyph_addr` = 0x80013CE8 (game 1 0x80013BD0, the same
code); the lead-byte test 0x8001202C is byte-identical to game 1's; glyph table A 0x8002063C (codes 0x8140-0x84BE,
524 x 22 bytes), kanji from 0x80023344. Hook, 74-letter font and scratch overwrite table A's Cyrillic/box glyphs
0x80022AD8-0x80023344 (the roll uses none: `tests/test_lint.py`). Rows are `font_en.fin_pairs` codes after the jp
line's leading single-byte codes (`insert.staff_en`); 28 letters per line with the indent (`tools/lint.py`).
The block cannot grow: a table follows the 0xFF, and the roll is addressed as lui/addiu 0x8001EC40 + u16 index at
~7 code sites (0x800111A4, 0x800111CC, 0x800112A8, 0x800112D8, 0x80011308, 0x80011340, 0x800113B8), not only through
the u32 at 0x35E90. English as first written was 189 bytes over, so name lines are indented 5 cells (JP: 6) instead;
the rewritten block ends with its own 0xFF and zeros up to the old one.
